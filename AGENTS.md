# Repository Instructions

## Purpose

Use this repository to maintain a practical roadmap for product design, frontend development, portfolio work, projects, and career growth.

## Planning conventions

- Keep current-quarter goals separate from long-term backlog.
- Give each goal a measurable completion condition.
- Link milestones to real repositories, documents, applications, or shipped work.
- Limit active priorities so the roadmap remains actionable.
- Review weekly and archive completed milestones monthly.
- Add dates only when they help commitment or sequencing.
- Record blockers and dependencies explicitly.

## Suggested documents

```text
design-roadmap.md
frontend-roadmap.md
portfolio-roadmap.md
project-backlog.md
resources.md
archive/
```

## Review checklist

1. What shipped since the previous review?
2. What evidence demonstrates progress?
3. Which goals are blocked or obsolete?
4. What is the smallest next deliverable?
5. Which backlog items should be removed?

## Do not

- Do not turn the repository into an endless resource dump.
- Do not mark vague intentions as milestones.
- Do not keep obsolete goals active for appearances.
- Do not describe the roadmap thumbnail as a runtime screenshot.
